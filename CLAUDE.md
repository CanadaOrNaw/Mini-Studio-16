# Mini Studio 16 — agent guide (CLAUDE.md)

Groovebox/synth/sampler/looper/MIDI firmware for the M5Stack Cardputer-ADV,
plus desktop tools, a static site, and printable hardware. Everything a
coding agent needs to build, test, flash, and drive the device lives here.
(P2-18 in the reconciliation report: this file is the hardware-day
onboarding for Claude Code/Codex-style agents. `AGENTS.md` points here.)

## Ground rules

- The integration branch is `agent/v3-alpha-sd-streaming`. `main` still
  mirrors upstream Microgroove until the maintainer flips it.
- Never claim hardware behavior from compile success. Pre-hardware claims
  come from the host suite; on-device claims need saved serial evidence
  (`docs/CARDPUTER_TESTING.md` defines the evidence format).
- The MG/303 engine is bit-locked to upstream (`synth_voice.h` +
  golden hash in `tests/test_synth_engine.cpp`); FM4 offline hashes are
  pinned too. Never change their rendered output; fix docs instead.
- Committed STL/SVG assets are deterministic generator output:
  edit `tools/generate_hardware_assets.py`, regenerate, and keep
  `--check` green. Never hand-edit the binaries.
- `docs/AUDIO_CAP_BOM.md` is generated by `tools/render_audio_cap_bom.py`
  from `hardware/audio-cap/bom.json`; regenerate, don't hand-edit.
- Back up the SD card before flashing development firmware.

## Build, test, verify (no hardware needed)

```bash
bash tests/run_host_tests.sh                      # full host suite (~2 min)
SANITIZER_SET=address,undefined bash tests/run_sanitizers.sh
python tools/generate_hardware_assets.py --check  # asset determinism
pio run -e m5stack-cardputer-adv                  # normal (USB device) image
pio run -e m5stack-cardputer-adv-usb-host         # USB host image
pio run -e mini-studio-audio-cap-atom-lite        # ATOM Lite Audio Cap
python tools/check_firmware_size.py .pio/build/m5stack-cardputer-adv/firmware.elf --max-static 204800
python tools/merge_firmware.py && python tools/merge_dual_firmware.py
python tools/build_site.py                        # static site -> build/pages
```

The suite has zero external dependencies beyond g++ and Python 3. Every
fix should extend it; a fix without a regression test is incomplete.

## Flash and drive the device

```bash
python tools/ministudio_cli.py ports              # find the serial port
esptool.py --chip esp32s3 --port PORT erase_flash # first flash / unbrick
esptool.py --chip esp32s3 --port PORT write_flash 0x0 mini-studio-16-dual-role.bin
python tools/ministudio_cli.py --port PORT status
python tools/hardware_smoke.py --port PORT --sd-test --output evidence/cardputer-smoke.json
python tools/protocol_soak.py --port PORT --count 10000
```

Download mode when the flasher can't connect: hold `G0`, tap reset,
release `G0` (screen stays blank — normal). Full beginner walkthrough:
`docs/FLASHING.md`. The `MS16/1` wire protocol and every command:
`docs/CONTROL_PROTOCOL.md` (the CLI mirrors it 1:1). USB-host role has no
CDC serial — switch roles with `boot-mode normal|host` or `Tab` at boot.

## Hardware-day plan

Work through `docs/CARDPUTER_TESTING.md` top to bottom; its intro tags
which steps are [AGENT]-drivable vs [HUMAN] (ears/hands/calipers), and
defines the `evidence/` + `results.json` conventions. Numeric gates:
`SDDIAG state=PASS`, write ≥ 500 KiB/s, reads ≥ 1,000 KiB/s, stalls
≤ 75 ms, `dspMisses=0`, `dropped=0`, twenty clean role round trips,
30-minute zero-drop captures.

Threading model in one line: core 0 renders audio from bounded SPSC rings;
core 1 runs UI/sequencer/serial plus dedicated storage workers that own
every SD file; cross-task state uses `__atomic` primitives — follow the
existing patterns (`pendingEngine`, seqlocks, consumer-owned ring resets)
when adding cross-task mutation.
